# คลังความรู้ความมั่นคงปลอดภัยไซเบอร์

เว็บไซต์รวบรวมเนื้อหาไว้อ่านทบทวน พร้อมแบบฝึกหัดคั่นระหว่างอ่าน แล็บให้ลงมือทำ และระบบสะสม EXP
ออกแบบให้ตัวอักษรใหญ่ (ฐาน 19px) อ่านสบายตา และเพิ่มเนื้อหาใหม่ได้เรื่อย ๆ โดยของเก่าไม่หาย

## เนื้อหาปัจจุบัน

| รหัส | หมวด | บทเรียน |
|---|---|---|
| CS-101 | พื้นฐานด้านความมั่นคงปลอดภัยไซเบอร์ | 6 (มีระดับก้าวหน้า 2 บท) |
| CS-201 | กฎหมายสำคัญที่เกี่ยวข้องกับความมั่นคงปลอดภัยไซเบอร์ | 4 |

ภาพประกอบ 76 ภาพ และคู่มือปฏิบัติ 19 ชุด รวม 110 ขั้นตอนที่ทำตามได้จริง

หมวด CS-601 ครบทั้งเจ็ดหมวดโจทย์ตามการแข่งขัน STDiO CTF คือ กลยุทธ์การแข่ง, Cryptography,
Web Application, Digital Forensics, Reverse Engineering และ Pwnable, Network Security,
Mobile Security และ Programming กับหัวข้อพิเศษ ทุกโจทย์ตรวจสอบแล้วว่าถอดได้เป็นธงจริง

## เนื้อหา CTF ครบทั้ง 7 หมวดในหลักสูตรเดียว

หมวด CS-601 รวมการเตรียมความพร้อมสำหรับการแข่งขัน CTF ไว้ในหลักสูตรเดียว 35 บท
เริ่มจากบทปฐมนิเทศและกลยุทธ์ ตามด้วยบทแนะนำและบทเจาะลึกของแต่ละหมวดเรียงต่อกัน
คือ Web (9 บท), Cryptography (5 บท), Digital Forensics (5 บท), Reverse และ Pwnable (4 บท),
Network Security (4 บท), Mobile Security (3 บท) และ Programming กับหัวข้อพิเศษ (3 บท)
พร้อมโจทย์ฝึก 65 ข้อที่กรอกธงตรวจคำตอบได้จริง

กระดานโจทย์ Jeopardy รวมโจทย์ทั้งหมดโดยจัดกลุ่มตามหมวดโดยอัตโนมัติ


## กระดานโจทย์ Jeopardy และกระดานคะแนน

หมวด CS-601 มีสองหน้าพิเศษที่เข้าได้จากปุ่มในหน้าหมวดหรือจากเมนูบัญชี

- **กระดานโจทย์ (`#/ctfboard`)** — แสดงโจทย์ทั้งหมดเป็นตารางแยกตามหมวดและคะแนนตามสไตล์ Jeopardy
  เลือกคลิกทำข้อไหนก่อนก็ได้ โจทย์ที่แก้แล้วขึ้นเครื่องหมายถูกสีเขียว พร้อมแถบความคืบหน้ารวม
- **กระดานคะแนน (`#/leaderboard`)** — ตารางอันดับผู้เรียนทุกคนเรียงตาม EXP
  แสดงระดับ จำนวนบทที่จบ แล็บ และจำนวนโจทย์ CTF ที่แก้ได้ พร้อมไฮไลต์อันดับของผู้ใช้ปัจจุบัน

กระดานคะแนนต้องมีฐานข้อมูล (ทำงานได้ทั้ง PostgreSQL และไฟล์ JSON) และนับเฉพาะผู้ที่เริ่มสะสม EXP แล้ว
ระบบนับจำนวนโจทย์ CTF แยกจากแบบฝึกหัดทั่วไป โดยดูจากคีย์สถานะที่ขึ้นต้นด้วย `ctf.`

## โจทย์ฝึกแบบ CTF

## เงื่อนไขการจบบทเรียน

ปุ่มบันทึกว่าเรียนจบถูกล็อกไว้จนกว่าผู้เรียนจะผ่านทุกเงื่อนไข กดข้ามไม่ได้

1. **ใช้เวลากับบทนั้นอย่างน้อย 40% ของเวลาที่ประเมินไว้** ขั้นต่ำ 2 นาที
   นับเฉพาะตอนที่แท็บเปิดอยู่จริง สลับไปแท็บอื่นแล้วเวลาจะหยุดนับ
2. **เลื่อนอ่านจนถึงท้ายบท**
3. **ตอบแบบฝึกหัดในบทถูกครบทุกข้อ**
4. **ทำแล็บในบทสำเร็จครบ** (เฉพาะบทที่มีแล็บ)

ระบบแสดงรายการเงื่อนไขพร้อมสถานะให้เห็นตลอด และอัปเดตทันทีเมื่อผู้เรียนทำผ่านแต่ละข้อ

## ติดตั้งเป็นแอปบนหน้าโฮมมือถือ

เว็บรองรับการติดตั้งเป็นแอป (PWA) แล้ว มีไฟล์ที่เกี่ยวข้องดังนี้

- `public/manifest.json` — ชื่อแอป สี ไอคอน และทางลัด
- `public/icon.svg` — ต้นฉบับไอคอน แก้ที่นี่แล้วสร้าง PNG ใหม่
- `public/icon-192.png`, `icon-512.png`, `icon-maskable-512.png` — ไอคอนสำหรับ Android
- `public/apple-touch-icon.png` — ไอคอนสำหรับ iOS ซึ่งต้องเป็น PNG ทึบ
- `public/sw.js` — service worker แบบผ่านตรง ไม่แคชอะไรเลย เพื่อไม่ให้ผู้เรียนเห็นเนื้อหาเก่าค้างหลัง deploy

**วิธีติดตั้งบนมือถือ** — Android เปิดใน Chrome แล้วเลือกเมนูสามจุด กด "ติดตั้งแอป"
ส่วน iOS เปิดใน Safari กดปุ่มแชร์ แล้วเลือก "เพิ่มไปยังหน้าจอโฮม"

> ต้องเปิดผ่าน HTTPS เท่านั้นจึงจะติดตั้งได้ ซึ่ง Railway ให้มาอยู่แล้ว

**ถ้าจะเปลี่ยนไอคอน** แก้ `public/icon.svg` แล้วสร้าง PNG ใหม่ด้วย

```bash
npm install --no-save sharp
node -e "
const sharp=require('sharp'),fs=require('fs');
const svg=fs.readFileSync('public/icon.svg');
(async()=>{
  for (const s of [192,512]) await sharp(svg).resize(s,s).png().toFile('public/icon-'+s+'.png');
  const core = await sharp(svg).resize(399,399).png().toBuffer();
  await sharp({create:{width:512,height:512,channels:4,background:'#0F2338'}})
    .composite([{input:core,gravity:'center'}]).png().toFile('public/icon-maskable-512.png');
  await sharp(svg).resize(180,180).flatten({background:'#0F2338'}).png().toFile('public/apple-touch-icon.png');
  await sharp(svg).resize(32,32).png().toFile('public/favicon-32.png');
})();
"
npm uninstall sharp
```

หมวด CS-401 ครอบคลุมเครื่องมือที่ใช้จริง ได้แก่ คำสั่งบน Command Prompt และ PowerShell,

## บัญชีผู้ใช้และฐานข้อมูล

เว็บมีระบบสมัครสมาชิก เข้าสู่ระบบ รูปโปรไฟล์ และระบบเพื่อน

- **รหัสผ่าน** แฮชด้วย `scrypt` ที่มีอยู่ใน Node.js อยู่แล้ว มี salt เฉพาะรายและ key stretching ในตัว
- **เซสชัน** เก็บในฐานข้อมูล ส่งผ่านคุกกี้แบบ `HttpOnly` `SameSite=Lax` และเป็น `Secure` เมื่อ `NODE_ENV=production`
- **รูปโปรไฟล์** ย่อเหลือ 256 พิกเซลในเบราว์เซอร์ก่อนอัปโหลด แล้วเก็บเป็น data URL ในฐานข้อมูล จึงไม่ต้องใช้บริการเก็บไฟล์แยก
- **ระบบเพื่อน** ส่งคำขอด้วยชื่อผู้ใช้ ตอบรับแล้วจึงเห็นระดับและ EXP ของกัน ไม่เห็นคำตอบของกันและกัน
- **ผู้ที่ไม่สมัครสมาชิก** ยังใช้งานได้ครบทุกอย่าง ความคืบหน้าเก็บใน localStorage และจะถูกรวมเข้าบัญชีอัตโนมัติเมื่อสมัครหรือเข้าสู่ระบบภายหลัง

### ที่เก็บข้อมูลสองแบบ

| เงื่อนไข | ที่เก็บ |
|---|---|
| มี `DATABASE_URL` | PostgreSQL สร้างตารางให้อัตโนมัติตอนเริ่มระบบ |
| ไม่มี | ไฟล์ `data/store.json` เหมาะกับการพัฒนาในเครื่อง |

โครงสร้างตารางคือ `users`, `sessions`, `progress`, `friends` ดูได้ใน `lib/db.js`

> ไฟล์ `data/store.json` อยู่ใน `.gitignore` แล้ว และ**ไม่ควรใช้บน Railway**
> เพราะระบบไฟล์ของ Railway ถูกล้างทุกครั้งที่ deploy ใหม่ ข้อมูลผู้ใช้จะหายหมด

## deploy ขึ้น Railway

1. push โค้ดทั้งหมดขึ้น GitHub
2. ที่ Railway เลือก **New Project → Deploy from GitHub repo** แล้วเลือก repo นี้
3. Railway จะตรวจเจอ `package.json` และรัน `npm start` ให้เอง ไม่ต้องตั้งค่า build command
4. ไปที่ **Settings → Networking → Generate Domain** เพื่อรับ URL สาธารณะ
5. กด **New → Database → Add PostgreSQL** ในโปรเจกต์เดียวกัน
   Railway จะสร้างตัวแปร `DATABASE_URL` ให้อัตโนมัติ และแอปจะสร้างตารางเองตอนเริ่มระบบ
6. ที่แท็บ **Variables** เพิ่ม `NODE_ENV` = `production`
   เพื่อให้แคชเนื้อหาในหน่วยความจำ และให้คุกกี้เซสชันเป็นแบบ Secure

> ถ้าไม่เพิ่ม PostgreSQL ระบบจะยังรันได้ แต่ข้อมูลผู้ใช้จะหายทุกครั้งที่ deploy ใหม่

พอร์ตถูกอ่านจาก `process.env.PORT` อยู่แล้ว จึงทำงานกับ Railway ได้ทันที

## เพิ่มเนื้อหาใหม่โดยไม่ให้ของเก่าหาย

เซิร์ฟเวอร์อ่านทุกไฟล์ `.js` ในโฟลเดอร์ `content/` โดยอัตโนมัติ (ยกเว้นไฟล์ที่ขึ้นต้นด้วย `_`)
การเพิ่มหมวดใหม่จึงทำได้ด้วยการเพิ่มไฟล์ใหม่เพียงไฟล์เดียว

```bash
cp content/_TEMPLATE.js content/04-network-security.js
```

จากนั้นแก้ในไฟล์ใหม่:

- `id` — ต้องไม่ซ้ำกับหมวดอื่น
- `order` — ลำดับที่แสดงในสารบัญ
- `code`, `title`, `subtitle`, `summary`, `objectives`
- `lessons` และ `finalQuiz`

commit แล้ว push ขึ้น GitHub — Railway จะ deploy ใหม่ให้เอง เนื้อหาเก่าอยู่ครบ

> **สำคัญ** ความคืบหน้าของผู้เรียนผูกกับ `id` ของหมวดและบทเรียน
> ถ้าเปลี่ยน `id` ของเนื้อหาที่มีคนเรียนไปแล้ว ความคืบหน้าเดิมจะไม่ถูกนับ
> การ**แก้ข้อความ**ในบทเรียนเดิมทำได้อิสระ ไม่กระทบความคืบหน้า

### ชนิดของบล็อกที่ใช้เขียนเนื้อหาได้

**เนื้อหา** — `h` (หัวข้อย่อย), `text` (ย่อหน้า HTML), `list`, `term` (คำศัพท์),
`table`, `note` (กล่องเน้น 4 แบบ: `info` `tip` `warn` `law`), `key` (สรุปท้ายบท),
`figure` (ภาพประกอบ), `code` (บล็อกคำสั่งพร้อมปุ่มคัดลอก),
`walk` (คู่มือปฏิบัติแบบทีละขั้น)

### บล็อก `walk` สำหรับเขียนคู่มือปฏิบัติ

```js
{
  type: 'walk',
  title: 'ติดตั้ง Wireshark บน Windows',
  meta: 'ใช้เวลาประมาณ 10 นาที · ต้องมีสิทธิ์ผู้ดูแลเครื่อง',
  steps: [
    {
      t: 'หัวข้อของขั้นตอน',
      d: 'คำอธิบาย ใช้ HTML ได้',
      cmd: 'sudo apt install -y wireshark',   // แสดงเป็นกล่องคำสั่งพร้อมปุ่มคัดลอก
      out: 'ผลลัพธ์ที่ควรเห็นบนหน้าจอ',
      tip:  'เคล็ดลับ (กล่องเขียว)',
      warn: 'ข้อควรระวัง (กล่องแดง)',
      fix:  'วิธีแก้เมื่อติดปัญหา (กล่องเหลือง)',
    },
  ],
  done: 'สิ่งที่ควรได้เมื่อทำครบทุกขั้น',
}
```

ทุกฟิลด์นอกจาก `t` เป็นตัวเลือก ใส่เฉพาะที่จำเป็น

**แบบฝึกหัด** — `quiz` (เลือกข้อเดียว), `multi` (เลือกหลายข้อ), `tf` (ถูก/ผิด),
`fill` (เติมคำ), `match` (จับคู่), `order` (เรียงลำดับ)

**แล็บ** — บล็อก `lab` พร้อมระบุ `tool` เป็นหนึ่งใน
`password` `hash` `phishing` `urlcheck` `pdpa` `risk` `checklist` `cert` `firewall`
`subnet` `nmapcmd` `wireshark` `snort` `cvss`

การเขียนแล็บใหม่ที่เป็นรูปแบบ "เลือกหนึ่งตัวเลือกต่อรายการ" หรือ "กรอกคำตอบเป็นข้อความ"
ใช้ตัวช่วย `choiceLab()` และ `textLab()` ใน `public/app.js` ได้เลย ไม่ต้องเขียนตรรกะการตรวจใหม่

ดูตัวอย่างการใช้งานครบทุกชนิดได้ใน `content/_TEMPLATE.js`

### ภาพประกอบ

ภาพทุกภาพเป็น SVG ที่เขียนด้วยโค้ด เก็บรวมไว้ใน `content/_figures.js` ไม่มีไฟล์รูปภาพในโปรเจกต์เลย
ข้อดีคือไม่มีปัญหาลิขสิทธิ์ คมทุกความละเอียด ใช้สีและฟอนต์เดียวกับเว็บ และแก้ข้อความในภาพได้เหมือนแก้โค้ด

```js
const F = require('./_figures');

{ type: 'figure', title: 'หัวข้อภาพ', svg: F.ciaTriad, caption: 'คำบรรยายใต้ภาพ' }
```

เพิ่มภาพใหม่ด้วยการเขียนฟังก์ชันใน `_figures.js` โดยมีตัวช่วยให้ใช้แล้วสามตัว
คือ `box()` วาดกล่องพร้อมข้อความหลายบรรทัด `t()` วางข้อความบรรทัดเดียว และ `line()` ลากเส้นพร้อมหัวลูกศร
ค่าสีทั้งหมดประกาศเป็นค่าคงที่ไว้ด้านบนของไฟล์ จึงเปลี่ยนธีมทั้งชุดได้จากจุดเดียว

### เพิ่มแล็บชนิดใหม่

เขียนฟังก์ชันใหม่ใน `public/app.js` ส่วน "12. แล็บ"

```js
LABS.myTool = (panel, done, alreadyDone) => {
  // panel   = element ให้วาง UI ของแล็บ
  // done()  = เรียกเมื่อผู้เรียนทำสำเร็จ ระบบจะให้ EXP และบันทึกให้เอง
};
```

แล้วอ้างถึงด้วย `{ type: 'lab', tool: 'myTool', ... }` ในไฟล์เนื้อหา

## ระบบ EXP

- อ่านจบบทเรียน — ตามค่า `exp` ของบทนั้น (50–90)
- ตอบแบบฝึกหัดถูกครั้งแรก +10 EXP, ตอบถูกในครั้งถัด ๆ ไป +4 EXP
- ทำแล็บสำเร็จ — ตามค่า `exp` ของแล็บ (50–60)
- แบบทดสอบท้ายหมวด — ข้อละ 15 EXP และโบนัส 30 EXP เมื่อได้เต็ม

ระดับคำนวณจากสูตร `EXP สะสมที่ต้องใช้ = 30 × (ระดับ² − 1)` มีทั้งหมด 10 ระดับพร้อมชื่อยศ

## การเก็บความคืบหน้า

เขียนลง `localStorage` ทันทีเสมอ เพื่อให้ใช้งานต่อได้แม้เน็ตหลุด
ถ้าล็อกอินอยู่จะซิงก์ขึ้นเซิร์ฟเวอร์แบบหน่วงเวลา 1.2 วินาที และซิงก์อีกครั้งตอนปิดแท็บ

เมื่อเข้าสู่ระบบบนเครื่องใหม่ ระบบจะ **รวม** ความคืบหน้าสองชุดเข้าด้วยกัน ไม่ใช่เขียนทับ
โดยยึด EXP ที่สูงกว่า รวมบทเรียนและแล็บที่ทำแล้วของทั้งสองชุด และเก็บคะแนนแบบทดสอบครั้งที่ดีที่สุด

ปุ่ม **บันทึกความคืบหน้าเป็นไฟล์** และ **นำเข้าไฟล์ความคืบหน้า** ในแถบด้านข้างยังใช้ได้เหมือนเดิม
